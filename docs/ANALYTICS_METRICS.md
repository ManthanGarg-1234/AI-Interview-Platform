# Analytics and Performance Metrics

## Evidence states

Every skill/performance signal is labeled:

- `SELF_DECLARED`: supplied by the student; not verified.
- `AI_INFERRED`: generated by an AI feature; advisory only.
- `ASSESSMENT_SUPPORTED`: supported by a graded assessment.
- `CODING_SUPPORTED`: supported by accepted/graded coding work.
- `RECRUITER_VERIFIED`: explicitly verified in a recruiter workflow.
- `CERTIFICATION`: supported by a recorded certification.

Evidence has source ID, timestamp, score, confidence basis (`static` or
`static+runtime`), and expiration/review policy. Evidence is not silently
overwritten; new observations create new records.

## Student metric formulas

All metrics are bounded 0-100 and include `sampleCount`, date range, and evidence
breakdown. If minimum evidence is not present, return `null` with
`INSUFFICIENT_DATA`.

- **Coding proficiency**: weighted mean of accepted coding task scores and
  normalized difficulty, with recency weighting. Failed attempts inform
  improvement but cannot be treated as positive evidence.
- **Technical knowledge**: weighted assessment score by subject and difficulty.
- **Aptitude**: weighted aptitude assessment score with attempt-quality rules.
- **Communication**: rubric score from completed AI/recruiter interviews with
  sufficient answer evidence.
- **Interview performance**: weighted interview evaluation categories.
- **Subject/topic mastery**: graded activity and assessment evidence grouped by
  taxonomy node.
- **Learning consistency**: completed planned study days divided by eligible
  planned days over the selected period, capped at 100.
- **Placement readiness**: a transparent weighted aggregate of technical,
  coding, aptitude, communication, profile completeness, and learning
  consistency only when each required component has sufficient evidence.

Exact weights are configuration records, versioned, and displayed to the user.
No score is presented as an objective hiring decision.

## Recruiter metrics

- jobs by status
- applications by stage
- stage conversion rate = entries into next stage / entries into current stage
- median stage duration
- assessment completion and pass rate
- interview completion and evaluation distribution
- selection rate and time-to-decision

All recruiter metrics are company-scoped and exclude unauthorized candidates.

## Admin metrics

Operational aggregates include user counts, active sessions, verified companies,
jobs, interviews, attempts, queue health, AI usage/cost, security events,
moderation workload, and successful hiring outcomes. Raw sensitive content is not
needed for dashboard aggregates.

## Data pipeline

Domain transactions emit outbox events. Workers normalize events into analytics
facts/snapshots asynchronously. Dashboard queries read bounded aggregates, not
unbounded event scans. Reprocessing is idempotent by event ID.

## Planner inputs

The study planner consumes approved goals, target role/company, deadline,
available study time, topic mastery, unfinished tasks, recent activity,
assessment gaps, coding history, and interview recommendations. Major schedule
changes create `PROPOSED` recommendations requiring student approval.
